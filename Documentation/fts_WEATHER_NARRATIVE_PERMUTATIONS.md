# FTS Weather Narrative Permutations

Source of truth: [Modules/Core/fts_weather_0.2.0-alpha.1.js](../Modules/Core/fts_weather_0.2.0-alpha.1.js), especially `buildNarrative()` at lines `4824-4877` and its helper functions.

## Scope

This document is exhaustive at the narrative-template level for the live summary weather line generated by the weather module.

It is not literally possible to dump every fully rendered final sentence, because several slots are open-ended at runtime:

- numeric temperature labels
- numeric depth and elevation labels
- numeric speed labels
- event names
- explicit precipitation type strings supplied by data

Accordingly, this document captures:

- every sentence family the module can emit
- every hardcoded phrase bucket used by the narrative builder
- every optional clause and conditional branch
- every built-in critical event name currently available to the suffix

This document covers the summary narrative line only. It does not catalog detail-panel prose such as climate notes, current tables, or activation-window text.

## Environment Routing

The narrative engine has three sentence families.

| Narrative family | Trigger |
| --- | --- |
| `surface` | Default for `offshore`, `coastal`, `inland`, and any locale whose environment resolves to `surface` |
| `underwater` | Any locale whose environment resolves to `underwater` |
| `subterranean` | `underdark` and any locale whose environment resolves to `subterranean` |

Important surface-only rule:

- chop narration is only appended on surface locations that support chop
- by default this means `offshore`, `coastal`, or a surface locale with biome `ocean` or `coastline`
- a surface page with a non-elevation depth token suppresses chop, even if it is otherwise coastal/offshore

## Slot Library

The summary line is assembled from the following runtime slots.

### Temperature Adjective

`<TEMP_ADJ>` can be:

- `frigid`
- `cold`
- `mild`
- `warm`
- `hot`

### Narrated Temperature Label

`<TEMP_LABEL>` is numeric and unit-sensitive:

- imperial: `<tempF> degrees fahrenheit`
- metric: `<tempC> degrees celsius`

### Skies

`<SKIES>` can be:

- `clear`
- `partly cloudy`
- `cloudy`
- `overcast`
- `stormy`

### Precipitation

If precipitation is present, the narrative uses:

`<PRECIP>` = `<PRECIP_BAND> <PRECIP_TYPE>`

`<PRECIP_BAND>` can be:

- `light`
- `moderate`
- `heavy`

Auto-derived precipitation types:

- surface: `snow`, `sleet`, or `rain`
- subterranean: `drip`

Explicit precipitation types are open-ended, but there is one important formatting note:

- they are canonicalized before narration
- this strips spaces, punctuation, and underscores
- as a result, custom values render as a single lowercase alphabetic token
- example: `freezing_rain` would narrate as `freezingrain`

If rainfall is `none`, the precipitation clause is omitted entirely.

### Direction

`<DIR>` can be:

- `north`
- `north-northeast`
- `northeast`
- `east-northeast`
- `east`
- `east-southeast`
- `southeast`
- `south-southeast`
- `south`
- `south-southwest`
- `southwest`
- `west-southwest`
- `west`
- `west-northwest`
- `northwest`
- `north-northwest`

### Surface Speed Label

For non-dead-calm surface wind, the phrase is:

`<SPEED_LABEL>` = `<kts> kts (<secondary>)`

Built-in surface buckets currently resolve to these labels:

| Branch | Imperial | Metric |
| --- | --- | --- |
| noncritical `<= 20%` | `3 kts (3 mph)` | `3 kts (5 km/h)` |
| noncritical `<= 40%` | `5 kts (6 mph)` | `5 kts (10 km/h)` |
| noncritical `<= 60%` | `8 kts (9 mph)` | `8 kts (14 km/h)` |
| noncritical `<= 80%` | `10 kts (12 mph)` | `10 kts (19 km/h)` |
| noncritical `> 80%` | `13 kts (15 mph)` | `13 kts (24 km/h)` |
| critical `light` | `16 kts (18 mph)` | `16 kts (29 km/h)` |
| critical `moderate` | `21 kts (24 mph)` | `21 kts (39 km/h)` |
| critical `heavy` | `28 kts (32 mph)` | `28 kts (51 km/h)` |
| critical `severe` | `39 kts (45 mph)` | `39 kts (72 km/h)` |

### Underwater Current Strength Phrases

`<CURRENT_STRENGTH>` can be:

- `dead calm`
- `light`
- `steady`
- `moderate`
- `strong`
- `heavy`
- `severe`
- `violent`

### Subterranean Airflow Phrases

`<AIRFLOW_STRENGTH>` can be:

- `dead calm`
- `a faint draft`
- `a steady draft`
- `a moderate draft`
- `a strong draft`
- `a heavy draft`
- `strong`
- `heavy`
- `severe`
- `violent`

### Chop Phrases

If chop is supported, the appended sentence can be:

- `The sea surface is smooth, with no chop.`
- `Sea chop is light.`
- `Sea chop is moderate.`
- `Sea chop is heavy.`
- `Sea chop is severe.`

### Underwater Visibility Sentences

The underwater branch always appends one of these visibility sentences:

- `Ambient light still reaches this depth, and visibility remains workable.`
- `Ambient light still reaches this depth, but suspended matter keeps visibility short.`
- `Ambient light has fallen into a blue-green twilight, and visibility is short.`
- `Ambient light is effectively gone here, leaving the water dark unless a light source is carried.`

If the active underwater current is critical, the visibility sentence gains this tail:

- ` The current disturbance cuts it down further.`

### Subterranean Visibility Sentences

The subterranean branch always appends:

- `Ambient visibility is dark by default, and only carried light or darkvision pushes beyond it.`

If an event is active, that sentence gains this tail:

- ` The active hazard further obscures the passages.`

### Event Suffix

If a critical event is active, every environment family may append:

`A <EVENT_SEVERITY> <EVENT_NAME> is in progress.`

`<EVENT_SEVERITY>` can be:

- `light`
- `moderate`
- `heavy`
- `severe`

`<EVENT_NAME>` is open-ended because region data can define additional events, but the shipped built-in event names are:

- `blizzard`
- `ice storm`
- `winter gale`
- `thunderstorm`
- `sea storm`
- `rogue wave`
- `hurricane`
- `tornado`
- `sandstorm`
- `heat wave`
- `flash flood`
- `wildfire`
- `earthquake`
- `volcanic eruption`
- `ashfall`
- `cave in`
- `sinkhole`
- `toxic fog`
- `maelstrom`

## Full Narrative Grammar

The following sections show every sentence family the summary line can produce.

### Surface Narrative

Surface pages use one of these intros:

```text
At <TEMP_LABEL>, the temperature is <TEMP_ADJ>, and the skies are <SKIES>
At an elevation of <ELEVATION_LABEL>, the temperature is <TEMP_ADJ>, and the skies are <SKIES>
At a depth of <DEPTH_LABEL> below the surface, the temperature is <TEMP_ADJ>, and the skies are <SKIES>
```

Optional precipitation clause:

```text
 with <PRECIP>
```

Then one of these wind clauses:

```text
. Wind is dead calm.
. Wind is coming from the <DIR> at about <SPEED_LABEL>.
```

Then, only on chop-capable surface locales, one of these chop sentences:

```text
 The sea surface is smooth, with no chop.
 Sea chop is light.
 Sea chop is moderate.
 Sea chop is heavy.
 Sea chop is severe.
```

Then, optionally:

```text
 A <EVENT_SEVERITY> <EVENT_NAME> is in progress.
```

Putting that together, the surface family is:

```text
<SURFACE_INTRO>[ with <PRECIP>]. <SURFACE_WIND>[ <SURFACE_CHOP>][ A <EVENT_SEVERITY> <EVENT_NAME> is in progress.]
```

Review notes:

- surface is the only family that narrates numeric temperature and sky state
- surface is the only family that narrates wind direction and speed
- surface is the only family that can append chop
- the `At a depth of <DEPTH_LABEL> below the surface` intro cannot coexist with chop, because a non-elevation depth token suppresses chop support

### Underwater Narrative

Underwater pages use one of these intros:

```text
At an unknown depth, the water feels <TEMP_ADJ>
At an elevation of <ELEVATION_LABEL>, the water feels <TEMP_ADJ>
At a depth of <FATHOMS_WITH_PREFERRED_LABEL>, the water feels <TEMP_ADJ>
```

Then one of these current clauses:

```text
 and the current is dead calm.
 and the current is <CURRENT_STRENGTH>.
```

Then one underwater visibility sentence:

```text
 Ambient light still reaches this depth, and visibility remains workable.
 Ambient light still reaches this depth, but suspended matter keeps visibility short.
 Ambient light has fallen into a blue-green twilight, and visibility is short.
 Ambient light is effectively gone here, leaving the water dark unless a light source is carried.
```

Possible visibility modifier:

```text
 The current disturbance cuts it down further.
```

Then, optionally:

```text
 A <EVENT_SEVERITY> <EVENT_NAME> is in progress.
```

Putting that together, the underwater family is:

```text
<UNDERWATER_INTRO><UNDERWATER_CURRENT> <UNDERWATER_VISIBILITY>[ A <EVENT_SEVERITY> <EVENT_NAME> is in progress.]
```

Review notes:

- underwater does not narrate skies
- underwater does not narrate precipitation
- underwater does not narrate numeric temperature in the summary line
- underwater uses current language, not wind language

### Subterranean Narrative

Subterranean pages use one of these intros:

```text
At an unknown depth, the air feels <TEMP_ADJ>
At an elevation of <ELEVATION_LABEL>, the air feels <TEMP_ADJ>
At approximately <SUBTERRANEAN_DEPTH_LABEL> below the surface, the air feels <TEMP_ADJ>
```

Optional moisture clause:

```text
, and <PRECIP> clings to the passages
```

Then one of these airflow sentences:

```text
. The airflow is dead calm.
. The airflow is <AIRFLOW_STRENGTH>.
```

Then the subterranean visibility sentence:

```text
 Ambient visibility is dark by default, and only carried light or darkvision pushes beyond it.
```

Possible visibility modifier:

```text
 The active hazard further obscures the passages.
```

Then, optionally:

```text
 A <EVENT_SEVERITY> <EVENT_NAME> is in progress.
```

Putting that together, the subterranean family is:

```text
<SUBTERRANEAN_INTRO>[, and <PRECIP> clings to the passages]. <SUBTERRANEAN_AIRFLOW> <SUBTERRANEAN_VISIBILITY>[ A <EVENT_SEVERITY> <EVENT_NAME> is in progress.]
```

Review notes:

- subterranean does not narrate skies
- subterranean does not narrate numeric temperature in the summary line
- subterranean can narrate moisture, but only through the `clings to the passages` clause
- subterranean uses airflow language, not open-air wind language

## Practical Editing Notes

- If the goal is to change summary-line diction, the primary review target is `buildNarrative()` plus the helper phrase buckets it calls.
- Locale, region, and seasonal data mostly change values fed into the sentence, not the sentence skeleton itself.
- The only summary-line wording that changes by environment family is:
  - surface wind and chop phrasing
  - underwater current and visibility phrasing
  - subterranean airflow and subterranean visibility phrasing
- The most open-ended slots are event names and explicit precipitation type strings supplied by data.
- If more natural explicit precipitation wording is desired, the current canonicalization of custom precipitation types is likely a good follow-up candidate for revision.
